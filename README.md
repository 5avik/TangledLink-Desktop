# TangledLink Desktop

Готовые локальные пакеты и бинарники Linux храним в `packages/linux/<версия>/`. При повторной сборке той же версии предыдущие файлы переносим в её `archive/`. Папку `packages/` Git игнорирует.

## Linux x86_64

Сборка использует GTK 3 и WebKitGTK 4.1. Интерфейс запускается от обычного пользователя. Системный пакет устанавливает Xray и отдельный TUN-помощник. Polkit запрашивает подтверждение администратора при создании туннеля. Для системного DNS нужен работающий systemd-resolved. Для сохранения сессии и подписки нужен доступный Secret Service, например GNOME Keyring.

```sh
sudo apt install ./tangledlink-desktop_1.0.1-1_amd64.deb
sudo dnf install ./tangledlink-desktop-1.0.1-1.x86_64.rpm
sudo pacman -U ./tangledlink-desktop-1.0.1-1-x86_64.pkg.tar.zst
```

Выполни одну команду для своей системы. После установки открой TangledLink Desktop из меню приложений или запусти `tangledlink-desktop`. Отдельный ELF подходит для запуска интерфейса с системными библиотеками. Для подключения он использует помощник из установленного пакета.

Команды сборки на Linux:

```sh
(cd desktop && npm ci && npm run build)
cargo build --release --locked --bin tangledlink-tun-helper
cargo build --release --locked --manifest-path desktop/Cargo.toml
bash packaging/linux/stage.sh STAGE desktop/target/release/tangledlink-app \
  target/release/tangledlink-tun-helper PATH_TO_XRAY PATH_TO_XRAY_LICENSE
```

В `packaging/linux` находятся шаблоны DEB, RPM и Arch. Распакованный Linux x64 Xray-core версии 26.11.9 используется без изменений. Для DEB положи `deb-control` в `STAGE/DEBIAN/control` и собери через `dpkg-deb --root-owner-group --build STAGE`. Для RPM и Arch создай `payload.tar` с каталогом `usr` из `STAGE` и используй соответствующий рецепт.

### Обновления Linux

Установленный клиент проверяет последний стабильный релиз TangledLink Desktop на GitHub. Для автообновления релиз с тегом `vX.Y.Z` должен содержать пакет текущего формата с опубликованным GitHub SHA-256. Используются имена из рецептов упаковки (`tangledlink-desktop-X.Y.Z-1-x86_64.pkg.tar.zst`, `tangledlink-desktop_X.Y.Z-1_amd64.deb`, `tangledlink-desktop-X.Y.Z-1.x86_64.rpm`). Первая установка пакета с поддержкой обновлений выполняется вручную.

После подтверждения пользователя клиент скачивает пакет, проверяет его и запрашивает разрешение Polkit. При успешной установке клиент перезапускается. Активный VPN отключается перед заменой пакета.

## Windows x64

Предварительная портативная сборка для Windows x64. Клиент загружает HTTPS-подписку, показывает список серверов VLESS + REALITY (TCP, gRPC и XHTTP) и запускает системный туннель через Xray и Wintun. При закрытии окна приложение остаётся в трее. Пункты меню трея позволяют открыть окно и завершить VPN.

## Запуск

1. Распакуй архив в отдельную папку и запусти **TangledLink.exe**. Windows запросит права администратора для настройки TUN.
2. Вставь ссылку тестовой подписки, нажми **Загрузить**, выбери сервер и нажми **Подключить**.
3. Чтобы завершить работу, нажми **Отключить** либо выбери **Отключить VPN и выйти** в трее.

Windows шифрует сессию аккаунта через DPAPI для текущей учётной записи. Интерфейс и управление туннелем Windows пока работают в одном процессе с повышенными правами.

При активном VPN можно выбрать другой сервер и нажать «Переключить». Клиент пересоздаёт туннель, поэтому возможен короткий разрыв. Если новый туннель не запускается, клиент пытается восстановить предыдущий.

В списке серверов есть поиск по названию и транспорту. При отключённом VPN кнопка «Задержка TCP» измеряет время установки прямого TCP-соединения с адресом каждого профиля. После замера список можно отсортировать. Проверка показывает доступность TCP-порта. Скорость и качество трафика внутри VPN она не измеряет.

В меню значка TangledLink доступны подключение к выбранному серверу и отключение VPN. При ошибке подключения клиент открывает окно с причиной.

## Вход в аккаунт

При запуске клиент проверяет сохранённую сессию или показывает окно входа. Введи логин и пароль, а если клиент попросит — код из письма. После авторизации клиент загружает серверы аккаунта. Ручной выход или истечение сессии возвращает к форме входа.

На экране входа доступны создание аккаунта с подтверждением почты и восстановление пароля. Для старых неактивированных логинов клиент запрашивает код активации и почту. Если для существующего аккаунта восстановление по почте недоступно, клиент показывает контакт поддержки.

В основном окне отображается доступность подписки аккаунта. Если сервер вернул сведения о трафике и сроке действия, клиент показывает суммарный расход, лимит и дату окончания.

## Сборка

Нужны Windows x64, Rust MSVC, Visual C++ Build Tools с Windows SDK, Node.js и WebView2 Runtime. В корне проекта выполни:

```powershell
Push-Location desktop
npm ci
npm run build
.\prepare-xray.ps1
Pop-Location
cargo build --manifest-path desktop/Cargo.toml --release --locked
```

Исполняемый файл находится в `desktop/target/release/tangledlink-app.exe`. Рядом создай папку `xray` и положи `xray.exe` и `wintun.dll` из официального [архива Xray-core v26.11.9 для Windows x64](https://github.com/XTLS/Xray-core/releases/tag/v26.11.9). При распространении сохрани соответствующие файлы лицензий.

Обработчик подписок и профилей находится в основном Rust-крейте. Управление процессом Xray и Win32-консолью выделено в `src/engine.rs`. Интерфейс и команды Tauri находятся в `desktop`.

## Установщик Windows

Выйди из TangledLink через трей перед установкой, обновлением или удалением. NSIS-установщик добавляет приложение в Program Files и меню «Пуск». Портативная версия и установленный клиент используют одни локальные настройки текущего пользователя Windows.

Чтобы собрать установщик из исходников в Windows, выполни из корня проекта:

```powershell
Push-Location desktop
npm ci
npm run build
.\prepare-xray.ps1
npx tauri build --ci --bundles nsis -- --locked
Pop-Location
```

Установщик появляется в `desktop/target/release/bundle/nsis`. Скрипт скачивает официальный Xray, проверяет SHA-256 и размещает ядро и лицензии в `desktop/xray`.

## Проверки

```text
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
```

Служебный CLI позволяет проверить конфигурации и кратковременно запустить один профиль на Windows. Файлы с подпиской храни в исключённой из Git папке `local`.

```powershell
cargo build --release --locked
.\target\release\tangledlink-desktop.exe check-subscription .\local\xray\xray.exe .\local\subscription.txt
.\target\release\tangledlink-desktop.exe trial .\local\xray\xray.exe .\local\subscription.txt 0 1
```

Индекс профиля отсчитывается с нуля. Пробный запуск проверяет HTTPS с системным DNS и сравнивает внешний IPv4 во время и после туннеля. На Windows x64 ядро приняло все десять тестовых конфигураций. Короткие прогоны по одному серверу каждого из трёх типов подтвердили изменение внешнего IP, завершение Xray и возврат исходных маршрутов по умолчанию. На тестовом ПК отсутствовал исходный IPv6-маршрут по умолчанию.

На том же ПК проверен сценарий в окне Tauri: загрузка десяти серверов по HTTPS, запуск VPN, закрытие окна при активном соединении, повторное открытие и отключение. Разовый замер суммы Private Working Set процессов клиента, Xray и WebView2 составил 100 МиБ с открытым окном и 38,2 МиБ с закрытым окном при активном VPN. После закрытия окна процессы WebView2 завершились. Замер выполнен на диагностической сборке с включённым локальным портом WebView2 для автоматизации.
